Animata **widgets** are small, glanceable React cards — the kind of thing you’d drop on a marketing bento, a dashboard tile, or an app home screen. They are **not** full app panels, video call UIs, or expandable multi-column layouts.

This page is the **published-only value audit** for the `widget-improvements` effort. It does not apply to components we have deliberately removed from the public catalog.

## Who we optimize for

**Developer (primary):** lands on a doc page and asks *“Is this the thing I need, and can I ship it with my data in five minutes?”*

**End user (secondary):** glances at the card in an app and gets **one fact** or **one obvious control** without reading copy.

If we cannot answer both, the component should not stay in the public widget list — regardless of animation quality.

## Value test (published catalog only)

Before investing in a widget, complete this in one sentence each:

| Question | If the answer is weak… |
| --- | --- |
| **Job** — What problem does this solve? | Unpublish or move to a `/demo` recipe only |
| **Glance** — What is the single hero element? | Simplify layout; do not add more props |
| **Ship** — Would a real product pin this on a home screen? | Not a widget; demote or delete |
| **Story** — Does Storybook show a recognizable scenario? | Fix the story first, then the API |
| **Own** — Can consumers pass their data without fighting the API? | Composition + props; if still awkward, unpublish |

### Apple HIG (web adaptation)

We borrow intent from [Apple’s widget HIG](https://developer.apple.com/design/human-interface-guidelines/widgets): one simple idea, balanced density, system-like type hierarchy, meaningful color — adapted to **web** (`size-52`, light/dark, `prefers-reduced-motion`, 44px touch targets). We are **not** building WidgetKit timelines.

**Default small family:** `size-52` (~208px), `p-4`, `rounded-3xl`, three text levels (hero / body / caption).

## Unpublished — do not republish

## Recommended backlog (`widget-improvements`)

### Wave 1 — Tier A (ship value users feel) — done on `widget-improvements`

Reminder, Weather Card, Water Tracker, VPN Connection, Delivery Card, Alarm Clock, Calendar Event, and Music Widget were updated with props, named stories, `size-52` / 44px controls, and “How it works” in docs.

**Next:** Wave 2 merges and Tier B reframes; Wave 3 unpublishes Tier C duplicates.

### Wave 2 — Tier B (one decision each)

- **Merge:** Battery + Battery Level → one “Device battery” widget  
- **Merge:** Storage Widget + Storage Status → one “Storage” widget  
- **Merge or unpublish:** Reminder vs Reminder Widget  
- **Reframe or unpublish:** Gooey Calendar, Popover Menu (document as marketing/nav, not home tiles)  
- **Charts:** Sleep Tracker, Score Board — tighten stories; consider `graphs/` cross-link  

### Wave 3 — Tier C (reduce catalog noise)

Unpublish with `published: false` (no deletion required): Flight Widget, Mobile Detail, Folder, Calorie Counter (or shrink + republish once), duplicate batteries/storage, Reminder Widget if Reminder wins.

### Explicitly out of scope

- Republishing Calendar Widget, Team Clock, Video Chat, Music Stack Interaction

## Checklist before keeping a widget published

- [ ] Job + glance answered in the MDX description (benefit, not feature list)  
- [ ] Story shows a recognizable product context  
- [ ] Default footprint is `size-52` (or documented medium variant)  
- [ ] Theme light/dark; no hover-only critical info  
- [ ] Touch targets ≥ 44px on interactive controls  
- [ ] `className` + `cn()`; consumer owns copy via props or children  
- [ ] Changelog entry when user-visible behavior ships
